# Module 1.2 — Installing & running Redis (Docker, `redis-cli`)

> **Goal:** Get a Redis server running, connect to it, and become fluent with `redis-cli` —
> the tool you'll live in for the rest of this roadmap. We focus on Docker (the cleanest,
> most reproducible way) and the CLI features that actually matter day-to-day.

---

## 1. The pieces you'll meet

```
┌────────────────┐         RESP over TCP          ┌──────────────────────┐
│   redis-cli    │ ─────────────────────────────► │     redis-server     │
│ (the client)   │ ◄───────────────────────────── │ (the actual database) │
└────────────────┘        default port 6379       └──────────────────────┘
        ▲                                                     │
        │                                          reads config from
   you type commands                                ┌──────────────┐
                                                     │  redis.conf  │
                                                     └──────────────┘
```

- **`redis-server`** — the server process (the database itself).
- **`redis-cli`** — the official command-line client.
- **`redis.conf`** — the configuration file (ports, persistence, memory limits, auth…).
- **Port 6379** — the default TCP port (antirez picked it as leet-speak for "MERZ").

## 2. Running Redis with Docker (recommended)

### 2.1 The fastest possible start
```bash
# Pull and run Redis, expose 6379, run in the background:
docker run --name my-redis -p 6379:6379 -d redis:7

# Talk to it with a CLI *inside* the same container:
docker exec -it my-redis redis-cli
127.0.0.1:6379> PING
PONG
```
`PONG` means you're connected. That's the "hello world" of Redis.

### 2.2 With persistence (so data survives a restart)
By default the container's data is ephemeral. Mount a volume and enable append-only mode:
```bash
docker run --name my-redis \
  -p 6379:6379 \
  -v redis-data:/data \
  -d redis:7 \
  redis-server --appendonly yes
```
- `-v redis-data:/data` — a named volume; Redis writes its dump/AOF files to `/data`.
- `--appendonly yes` — turn on the AOF persistence log (Module 4.2).

### 2.3 With a custom config file
```bash
docker run --name my-redis \
  -p 6379:6379 \
  -v /path/to/redis.conf:/usr/local/etc/redis/redis.conf \
  -v redis-data:/data \
  -d redis:7 \
  redis-server /usr/local/etc/redis/redis.conf
```

### 2.4 docker-compose (nice for local dev)
```yaml
# docker-compose.yml
services:
  redis:
    image: redis:7
    ports:
      - "6379:6379"
    volumes:
      - redis-data:/data
    command: ["redis-server", "--appendonly", "yes"]
volumes:
  redis-data:
```
```bash
docker compose up -d
docker compose exec redis redis-cli PING
```

> **Tip:** For exploring the full feature set (search, JSON, time-series, probabilistic
> structures), use the **`redis/redis-stack`** image, which bundles the official modules
> plus RedisInsight (a web GUI) on port 8001.

## 3. Connecting with `redis-cli`

```bash
# Local default:
redis-cli

# Remote host / port:
redis-cli -h 10.0.0.5 -p 6380

# With auth (password / ACL user):
redis-cli -a 'yourpassword'                 # (warns about password on CLI)
redis-cli --user alice --pass 's3cret'

# Pick a database number (Redis has 16 logical DBs by default, 0–15):
redis-cli -n 2

# Connect over TLS:
redis-cli --tls --cert client.crt --key client.key --cacert ca.crt -h host -p 6379
```

Two ways to run commands:
```bash
# Interactive (a REPL):
redis-cli
127.0.0.1:6379> SET hello world
OK

# One-shot (great for scripts):
redis-cli SET hello world
redis-cli GET hello
```

## 4. Your first commands (the universal basics)

```bash
127.0.0.1:6379> SET name "Yatharth"      # store a string
OK
127.0.0.1:6379> GET name
"Yatharth"
127.0.0.1:6379> EXISTS name              # 1 = yes, 0 = no
(integer) 1
127.0.0.1:6379> EXPIRE name 60           # auto-delete in 60 seconds
(integer) 1
127.0.0.1:6379> TTL name                 # seconds left to live
(integer) 57
127.0.0.1:6379> TYPE name                # what data type is this key?
string
127.0.0.1:6379> DEL name                 # delete
(integer) 1
127.0.0.1:6379> KEYS *                   # ⚠️ list ALL keys (NEVER in prod)
(empty array)
```

> ⚠️ **`KEYS *` is a trap.** It scans the entire keyspace and blocks the single-threaded
> server. In production, always use **`SCAN`** (cursor-based, incremental):
> ```bash
> redis-cli --scan --pattern 'user:*'        # safe iteration
> ```

## 5. `redis-cli` features worth knowing

| Feature | Command | What it does |
|---|---|---|
| **Health check** | `redis-cli PING` | `PONG` if alive |
| **Server stats** | `redis-cli INFO` | Memory, clients, persistence, replication, stats |
| **Live command feed** | `redis-cli MONITOR` | Streams every command the server runs (debug only — slows the server) |
| **Safe key scan** | `redis-cli --scan` | Cursor-based iteration of keys |
| **Latency check** | `redis-cli --latency` | Measures round-trip latency continuously |
| **Big-key finder** | `redis-cli --bigkeys` | Samples the keyspace for memory hogs |
| **Memory of a key** | `MEMORY USAGE key` | Bytes used by one key |
| **Benchmark** | `redis-benchmark` | Load-test throughput/latency |
| **Run a Lua script** | `redis-cli --eval x.lua` | Execute server-side scripts (Module 3.4) |

```bash
# A quick throughput benchmark (50 parallel clients, 100k SET+GET ops):
redis-benchmark -t set,get -n 100000 -c 50 -q
# SET: 142857.14 requests per second
# GET: 158730.16 requests per second
```

## 6. The config file — the knobs you'll actually touch

`redis.conf` is plain `key value` lines. The ones that matter early:

```conf
bind 127.0.0.1 -::1        # which interfaces to listen on (security!)
protected-mode yes         # refuse risky remote access without auth (Module 11.2)
port 6379                  # listen port
requirepass "s3cret"       # legacy single password (prefer ACLs, Module 11.2)
maxmemory 2gb              # cap memory usage (Module 5)
maxmemory-policy allkeys-lru   # what to evict when full (Module 5.3)
appendonly yes             # AOF persistence (Module 4.2)
save 3600 1 300 100        # RDB snapshot rules (Module 4.1)
```

You can also change most settings **at runtime without restarting**:
```bash
127.0.0.1:6379> CONFIG GET maxmemory
1) "maxmemory"
2) "0"
127.0.0.1:6379> CONFIG SET maxmemory 256mb
OK
127.0.0.1:6379> CONFIG REWRITE          # persist runtime changes back to redis.conf
OK
```

## 7. Logical databases & namespacing

Redis has **16 numbered databases** (0–15) by default, selected with `SELECT`:
```bash
127.0.0.1:6379> SELECT 1
OK
127.0.0.1:6379[1]> SET k v
```
**But** in practice — and *especially* in Cluster (Module 7), which only supports DB 0 —
the idiomatic approach is **not** to use numbered DBs for separation. Instead, **namespace
your keys** with prefixes:
```
user:1000:profile
user:1000:sessions
order:55:items
```
The `:` convention is universal and tools (RedisInsight, etc.) render it as a tree.

## 9. Interview drills

**Q1 (junior). How do you check a Redis server is alive?**
`redis-cli PING` → expects `PONG`.

**Q2 (junior). What's the default Redis port?**
6379.

**Q3 (mid). Why should you never run `KEYS *` in production?**
It's O(n) over the whole keyspace and blocks the single-threaded server while it runs,
stalling all other clients. Use `SCAN` (cursor-based, incremental) instead.

**Q4 (mid). How do you change `maxmemory` without restarting Redis?**
`CONFIG SET maxmemory 256mb` at runtime, and `CONFIG REWRITE` to persist it to the config
file so it survives a restart.

**Q5 (senior). Numbered DBs (SELECT) vs key prefixes for separating data — which and why?**
Prefer key prefixes (`app:entity:id`). Numbered DBs aren't supported in Cluster mode (only
DB 0), don't provide real isolation (shared memory/CPU/config), and complicate connection
management. Prefixes are portable and Cluster-friendly.

---

## 10. Key takeaways
1. `docker run -p 6379:6379 -d redis:7` + `redis-cli PING` → you're live.
2. Add a **volume** + `--appendonly yes` for data that survives restarts.
3. Master `redis-cli`: `INFO`, `--scan`, `--bigkeys`, `--latency`, `MONITOR`, `redis-benchmark`.
4. Never `KEYS *` in prod — use `SCAN`.
5. Tune via `redis.conf` or live `CONFIG SET` + `CONFIG REWRITE`.
6. Namespace with `key:prefixes`, not numbered DBs.
